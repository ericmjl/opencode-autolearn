# Memory Insight - Low-Level Design

**Created**: 2026-06-25
**HLD Link**: ../../high-level-design.md

## Overview

The Memory Insight subsystem replaces autolearn's static, character-capped
`memory.md` with a **durable registry + dynamically composed context view**, and
adds three behaviours that were missing:

1. **Ebbinghaus retention** — each memory carries a decaying retention score;
   forgetting is driven by decay, not by line count.
2. **Recurring-preference detection** — a cross-session SW/EMA shift detector
   catches "the user keeps saying X" (rising) and "the user stopped saying X"
   (falling = a successful learning).
3. **An inspector UI** — a CLI-launchable local web app to explore everything
   stored, including each memory's retention curve.

This LLD covers five components that share one data-model spine:
`registry.py`, `retention.py`, `composer.py`, `shift.py`, `inspector_server.py`.
New modules live alongside `autolearn.py` in
`skills/autolearn-reviewer/scripts/`; `autolearn.py` imports them and adds
thin subparser wiring.

## Context — why replace memory.md

`memory.md` today conflates two distinct concerns: **durability** (should this
lesson survive?) and **relevance** (should it be in *this* session's context?).
A 3000-char FIFO cap answers neither — it silently chops the oldest line when
full, so still-valid lessons vanish (staleness) while their reinforcement
counters live on as orphans in `strengths.json`. The cap also forces the
Ebbinghaus curve to compete with a contradicting "oldest line" eviction policy.

The fix is to **separate store from view**:

```
Memory Registry (memories.jsonl)         ← durable, UNBOUNDED store; Ebbinghaus-governed
   one record per memory {text, type, topics, created_at, reinforcements[],
                          pinned, retention_score, tier, status}
        │
        │  composer.compose()  — rank by relevance × retention,
        │                        pack into a soft char budget
        ▼
memory.context.md  (~3000 chars)         ← generated per session, loaded into context
```

`opencode.json` instructions point at the generated `memory.context.md`
(regenerated by the plugin on session start and after each review). The legacy
`memory.md` / `user-profile.md` / `strengths.json` migrate into the registry
once and then retire.

## Data Models

### Memory Record (`memories.jsonl`)

JSONL file under the persona dir; one JSON object per line. Unbounded — no
character cap. The registry is the single source of truth; `strengths.json` is
subsumed (reinforcement data lives inside each record).

| Field | Type | Description |
|-------|------|-------------|
| id | string | Stable slug (python-slugify of `text`, truncated). Primary key. |
| text | string | The lesson / preference, verbatim. |
| type | `"memory"` \| `"user"` | Origin store (memory.md vs user-profile.md). |
| created_at | string | ISO date the memory was first recorded. |
| reinforcements | string[] | ISO dates of each strengthen event (oldest→newest). `created_at` is implicitly the first. |
| last_reinforced | string | `max(reinforcements)` if any, else `created_at`. |
| pinned | bool | If true, always included in the composed context (bypasses relevance ranking; still counts toward budget). |
| topics | string[] | Lexical topic tokens derived from `text` (lowercased, stopword-stripped, de-duplicated). Used for relevance matching and shift detection. |
| status | `"active"` \| `"evicted"` | `evicted` = decayed out of the registry after the grace period. |
| evicted_at | string\|null | ISO date status flipped to evicted. |
| retention_score | float | Cached 0..1 score, computed by `retention.py`. |
| tier | `"hot"`\|`"warm"`\|`"cold"`\|`"evictable"` | Cached tier derived from score. |
| scored_at | string\|null | ISO date `retention_score`/`tier` were last computed. |

### Topic Sighting (`topics.jsonl`)

Append-only JSONL; one row per (topic signature × session). Feeds the shift
detector.

| Field | Type | Description |
|-----------|------|-------------|
| topic_sig | string | Stable hash of the normalized token set. |
| tokens | string[] | The normalized tokens (for display + Jaccard). |
| session_id | string | OpenCode session id (or date if unavailable). |
| date | string | ISO date of the session. |
| count | int | Times this signature appeared in that session. |
| text_sample | string | Short snippet of a triggering utterance. |

### Candidate (`candidates.jsonl`)

JSONL; rising topics not yet promoted to memory. Surfaced in the UI for
one-tap confirm/dismiss.

| Field | Type | Description |
|-----------|------|-------------|
| id | string | UUID-ish id for the candidate. |
| topic_sig | string | Links to `topics.jsonl`. |
| tokens | string[] | Normalized tokens. |
| sw | float | Short-term (sliding-window) mean count. |
| ema | float | Long-term exponential moving average. |
| divergence | float | `\|sw − ema\|` (the shift signal). |
| direction | `"rising"` \| `"falling"` | `sw > ema` ⇒ rising. |
| first_seen | string | ISO date first sighted. |
| sessions | string[] | Session ids/dates that contributed. |
| utterances | string[] | Up to N sample utterances. |
| status | `"pending"` \| `"confirmed"` \| `"dismissed"` | Confirmation state. |
| created_at | string | ISO date the candidate was created. |

### Config additions (`config.yaml`)

```yaml
# Retention (Ebbinghaus)
retention_lambda: 0.03          # per-day decay; half-life ~23 days
retention_sigma: 0.3            # reinforcement boost strength
retention_salience_memory: 0.85 # base salience for type=memory
retention_salience_user: 0.80   # base salience for type=user
tier_hot: 0.7
tier_warm: 0.4
tier_cold: 0.15
eviction_grace_days: 90         # days below cold before status→evicted

# Context composer
context_budget_chars: 3000      # soft budget for memory.context.md

# Shift detector
shift_window: 3                 # sessions for the short-term sliding window
shift_beta: 0.7                 # EMA decay
shift_divergence_threshold: 0.5 # min |sw−ema| to flag an accelerating candidate
shift_recurrence_floor: 1.0     # steady-recurrence trigger: sw >= floor also flags a candidate
shift_min_sessions: 2           # sessions a topic must appear in before signalling
shift_max_candidates: 20        # cap pending candidates
```

## Component APIs

All modules import nothing from `autolearn.py`; `autolearn.py` imports them.
Each module exposes a small functional API + `cmd_*` handlers that `autolearn.py`
wires to subparsers. Tests live in `test_<module>.py` siblings (pytest, run via
`uv run pytest`).

### registry.py — `MemoryRegistry`

The foundation. Every other module imports this.

```python
REGISTRY_FILE = "memories.jsonl"

class MemoryRegistry:
    def __init__(self, persona_dir: Path): ...
    def load(self) -> list[dict]:              # all records (active + evicted)
    def load_active(self) -> list[dict]:       # status == "active"
    def get(self, id: str) -> dict | None
    def find_by_text(self, text: str) -> dict | None     # slug match
    def add(self, text, type, pinned=False, topics=None) -> dict
    def reinforce(self, id, when=None) -> dict           # append reinforcement date
    def update(self, record: dict) -> None               # write-back (e.g. score/tier)
    def remove(self, id) -> None
    def set_pinned(self, id, bool) -> None
    def set_status(self, id, status, when=None) -> None
    def save(self, records: list[dict]) -> None          # atomic tmp+rename

def slugify_text(text) -> str
def extract_topics(text) -> list[str]       # lowercase, strip punct/stopwords, dedupe
def migrate_from_legacy(persona_dir) -> int # returns count migrated; idempotent
```

**Lazy migration:** the first `load()`/`load_active()` call on a persona whose
`memories.jsonl` does not exist triggers `migrate_from_legacy`, which reads
`memory.md` + `user-profile.md` (via the same `_extract_entries` logic) and
`strengths.json`, emitting one record per entry. Migration is idempotent
(guarded by a `# migrated` marker file or by checking the registry already
exists). `created_at`/`reinforcements` come from `strengths.json`
(`first_seen`, `count` synthetic timestamps) when available.

**Atomic writes:** `save()` writes to `memories.jsonl.tmp` then `os.replace`.

### retention.py — Ebbinghaus scoring + eviction

```python
def compute_score(record, config) -> float
def tier_of(score, config) -> str                      # hot|warm|cold|evictable
def score_all(registry, config) -> dict                # writes score/tier/scored_at back; returns summary
def eviction_candidates(registry, config) -> list[dict]# active + tier==evictable + cold-since > grace
def cmd_retention_score(args)
def cmd_retention_evict(args)                           # --dry-run supported
def curve_points(record, config, days=90) -> list[tuple[date,float]]  # for the UI sparkline
```

**Formula** (embedding-free, adapted from AgentMemory `retention.ts`):

```
salience     = base[type] + min(0.2, len(reinforcements) * 0.02)   # capped ≤1
temporal     = exp(-retention_lambda * days_since_created)
boost        = retention_sigma * Σ(1 / days_since_each_reinforcement)   # skip 0-day
retention    = min(1, salience * temporal + boost)
```

Eviction flips `status` to `evicted` only after a record has been continuously
`evictable` (score < `tier_cold`) for `eviction_grace_days`. Evicted records
remain in the registry (for UI history) but are excluded from the composer.

### composer.py — dynamic context view

```python
def relevance(record, ctx_tokens: set[str]) -> float    # Jaccard over topics+text tokens
def compose(registry, ctx_tokens: set[str], config) -> str   # returns markdown text
def cmd_compose(args)                                    # writes persona_dir/memory.context.md
```

**Composition algorithm:**
1. Candidates = active, non-evicted records.
2. Force-include all `pinned` records first.
3. Rank remaining by `relevance × retention_score`.
4. Greedily append entries until `context_budget_chars` is reached (always keep
   ≥ pinned entries even if over budget).
5. Emit as the existing `# Autolearn Memory` markdown bullet format so
   `opencode.json` instructions loading is unchanged.

Session context tokens come from a `--context` CLI flag (plugin passes project
name + first user message + cwd). With no context, ranking falls back to
retention-only (hottest first).

### shift.py — recurring-preference detector

```python
def extract_signature(text) -> tuple[str, list[str]]    # (sig_hash, tokens)
def record_sightings(messages, session_id, date) -> int # appends topics.jsonl
def scan(registry, config) -> list[dict]                 # updates candidates.jsonl; returns new candidates
def cmd_topics_scan(args)
def cmd_topics_candidates(args)                          # list pending
```

**Pipeline (run from the reviewer cycle / curator):**
1. For each candidate user utterance (lexical correction/preference cues),
   compute `extract_signature`.
2. Append sightings to `topics.jsonl`.
3. Per `topic_sig`: `SW` = mean count over last `shift_window` sessions;
   `EMA ← shift_beta·EMA + (1−shift_beta)·count`.
4. `divergence = |SW − EMA|`; if ≥ threshold and ≥ `shift_min_sessions`
   sightings → upsert candidate (direction = rising if SW>EMA).
5. **Rising + matches existing memory** → auto `registry.reinforce`.
   **Rising + novel** → `candidates.jsonl` (status=pending) for UI surfacing.
   **Falling** (SW<EMA after prior rising) → mark as "learned" in the UI feed.

### inspector_server.py — `autolearn ui`

```python
def serve(port: int, persona_dir: Path, open_browser: bool = True)
def cmd_ui(args)
```

**Tech:** Python stdlib `http.server.ThreadingHTTPServer` + one embedded HTML
page (vanilla JS, inline SVG sparklines). No build step, no external frontend
deps. Read-only by default; a small set of POST endpoints mutate the registry
via the `registry`/`shift` APIs.

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/` | GET | Single-page app shell |
| `/api/overview` | GET | Bucket counts, candidate counts, orphan warnings |
| `/api/memories` | GET | All registry records (type, score, tier, trend) |
| `/api/memory/{id}` | GET | One record + `curve_points` sparkline data |
| `/api/candidates` | GET | Pending candidates |
| `/api/learned` | GET | Falling candidates (successful learnings) |
| `/api/skills` | GET | Reuses existing skill list/usage |
| `/api/activity` | GET | `observations.jsonl` recent events |
| `/api/memory/{id}/strengthen` | POST | reinforce + rescore |
| `/api/memory/{id}/weaken` | POST | manual weaken |
| `/api/candidate/{id}/confirm` | POST | promote to memory |
| `/api/candidate/{id}/dismiss` | POST | status→dismissed |

## CLI Commands (added to autolearn.py)

| Command | Description |
|---------|-------------|
| `ui [--port 4321] [--no-browser]` | Launch the inspector UI |
| `retention score` | Rescore all records; write score/tier back |
| `retention evict [--dry-run]` | Evict records past the cold grace period |
| `memory compose [--context TEXT]` | Generate `memory.context.md` |
| `topics scan` | Run the shift detector over recent sessions |
| `topics candidates` | List pending candidates |

Existing `memory add/remove/strengthen/weaken` are re-pointed at the registry
(they become thin wrappers over `MemoryRegistry`). `memory list` continues to
print the *composed* view by default so current reviewer behaviour is
preserved.

## Plugin Integration (`plugin/autolearn.js`)

- The `instructions` entry currently pointing at `memory.md` is migrated to
  `memory.context.md` (one-time, auto).
- On **session start** and **after each review**, the plugin shells out to
  `autolearn.py memory compose --context "<project> <first-user-msg>"` to
  regenerate the file before the agent reads it. (Same spawn mechanism already
  used for sync.)

## Error Handling

| Condition | Behaviour |
|-----------|-----------|
| `memories.jsonl` missing | Triggers lazy migration; if legacy files also absent, starts empty. |
| Corrupt JSONL line | Skip the line, log to `debug.log`; never crash the CLI. |
| `memory compose` with empty registry | Writes a minimal valid `memory.context.md` (header only). |
| UI port in use | Try the requested port, then increment up to +10, print the chosen URL. |
| Concurrent writes (UI + reviewer) | Atomic tmp+rename per save; last writer wins. No cross-process lock (single-user). |

## Edge Cases

1. **Orphan strengths during migration:** a `strengths.json` slug whose text was
   already trimmed from `memory.md` — migrate it anyway (text reconstructed
   from the slug heuristically is bad, so **skip** orphans and report the
   count). The UI surfaces the skip count.
2. **Reinforcement of an evicted memory:** `reinforce()` flips `status` back to
   `active` and resets `evicted_at` (a lesson came back).
3. **Pinned over budget:** pinned entries are always emitted even if total
   exceeds the budget.
4. **First run after upgrade:** migration runs, `memory.md` is preserved on
   disk (renamed `memory.md.legacy`) but no longer loaded; composer takes over.

## Dependencies

- **Python ≥3.11** (already required), stdlib only for all five modules.
- **python-slugify** (already an `autolearn.py` dep) for `slugify_text`.
- No new third-party dependencies. No embeddings, no vector store, no Node for
  the UI.

## Build Order (dependency-aware)

1. `registry.py` + migration (foundation; everything imports it).
2. `retention.py` (depends on registry).
3. `composer.py` (depends on registry + retention).
4. `shift.py` (depends on registry).
5. `inspector_server.py` (depends on registry + retention + shift).
6. `autolearn.py` subparser wiring + plugin `compose` hook (integration).

Steps 2–5 are file-disjoint and are implemented by parallel subagents against
the frozen `registry.py` API; step 6 is a single integration pass.
